Comportamiento responsive:

encabezado:
Cuando la página se estrecha poco a poco y la lista del menú ya no cabe en la pantalla, cada ítem del menú pasa a la siguiente linea ya que el contenedor utiliza flex-wrap:wrap para darle ese diseño responsive, el menú y el título de la página no se combinan uno encima del otro, y si se sigue estrechando, se inicia un scroll horizontal en el navegador.

pie de página:
Cuando la página se estrecha lo suficiente los ítem del footer no se anteponen uno encima del otro, mantienen un mínimo de distancia y si se sigue estrechado se inicia un scroll horizontal en el navegador.

Flexbox o Grid: decisiones de layout

Portada: Usé grid debido a que el equipo de Nodo Digital pide en el boceto que la portada contenga el texto a la izquierda y una foto a la derecha, por lo que es necesario utilizar grid para dividir ambos ítems en dos columnas.
Galería: Usé grid debido a que el equipo pide la galería con tres rutas guiadas en una fila, por lo que se deben de distribuir en tres columnas cada contenedor de las rutas.
Reservas: Usé grid debido a que era necesario crear dos columnas para poder pasar la sección del horario al lado derecho del formulario y poder aplicar la distribución exacta 2:1 con grid-template-columns.
Fila del formulario: Usé Flexbox debido a que son solo dos campos en una linea. (una dimensión)
Encabezado: Usé Flexbox debido a que era necesario acomodar el título a la izquierda y el menú a la derecha, no habían filas ni columnas que se tuvieran que alinear entre sí.
Pie: Usé Flexbox debido a que solo debía de alinear horizontalmente tres textos cortos en una fila, es un flujo lineal, sin proporciones entre columnas.

Conclusión: Grid para la estructura general de cada página y Flexbox para alinear el contenido interno de un componente.

Problemas encontrados y cómo los resolví:

1. La portada no se ponía en dos columnas.
   Causa: escribí grid-template-columns: 1fr, 1fr; con coma, y DevTools
   mostraba la línea tachada con una advertencia. Solución: separar los
   valores con espacio (1fr 1fr).

2. El horario de atención quedaba debajo del formulario en reservas.
   Causa: el <aside> estaba fuera del contenedor Grid. Solución: poner
   <section> y <aside> dentro del mismo <div class="reservas-layout">.

3. La tabla de recorridos hacía scroll horizontal a 360 px.
   Causa: tiene 5 columnas y el relleno y la letra eran demasiado grandes.
   Solución: envolver las tablas en .tabla-scroll (overflow-x: auto),
   reducir font-size y padding en móvil, y volver a los valores normales
   desde 768 px.

4. El encabezado se veía igual en móvil y en escritorio.
   Causa: la regla global header { justify-content: space-between } era de
   escritorio y afectaba a todos los <header>. Solución: usar
   body > header con flex-direction: column en la base y volver a row
   en el media query de 768 px.

5. La última tarjeta de servicios quedaba sola a 1200 px.
   Causa: 4 tarjetas en 3 columnas dejan una huérfana. Solución:
   .servicio:last-child {grid-column: span 3;} dentro del media query
   de 1200 px.

Comparación: CSS Grid propio vs. grilla de Bootstrap (Nuestra flota)

Tiempo invertido:
Reconstruir la flota solo con la grilla de Bootstrap: 19:03 min.

Líneas de CSS de distribución vs. clases usadas:

|                          | Versión propia (CSS Grid)                           | Versión Bootstrap                            
|--------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------|
| Distribución de columnas | 3 líneas en .nuestra-flota1 (display: grid, grid-template-columns: repeat(auto-fit, minmax(...)), gap) | 0 líneas de CSS                                                               |
| Clases en HTML           | 1 clase (nuestra-flota1)                            | 31 clases (container (1) + row g-3 (2) + col-12 col-sm-6 col-lg-4 col-xl-3 en cada una de las 7 tarjetas (28 clases de columna)) |
| Puntos de quiebre        | 0 media queries (lo resuelve auto-fit)              | 3 (576, 992 y 1200 px) más la base                                                                                               |

¿Qué me dio Bootstrap sin esfuerzo?
- Una grilla responsive de 12 columnas ya probada, sin escribir CSS.
- Puntos de quiebre estándar (sm, lg, xl) con nombres claros.
- Gutters uniformes con una sola clase (g-3).
- Un contenedor (container) con anchos máximos por pantalla.

¿Qué control perdí?
- El número de columnas lo fijan los puntos de quiebre de Bootstrap (576, 992, 1200 px), no el espacio real disponible. Con auto-fit y minmax las columnas se ajustaban a cualquier ancho.
- El HTML se llenó de clases (col-12 col-sm-6 col-lg-4 col-xl-3 repetido 7 veces) y apareció un <div> extra por tarjeta.
- Dependo de un archivo externo (CDN) y del peso de todo Bootstrap para usar solo la grilla.
- Para cambiar la distribución hay que editar cada tarjeta, en vez de una sola regla en el CSS.

Conclusión:
Mi versión con CSS Grid necesitó menos código y menos clases, y se adapta a cualquier ancho. 
Bootstrap fue útil por la rapidez de partir de una grilla ya hecha y por los puntos de quiebre estándar, pero a cambio de más marcado en el HTML y menos control fino.

Clases encontradas en la documentción de Bootstrap:
1. text-decoration-none: quita el subrayado del enlace
2. bg-warning: fondo amarillo.
3. text-dark: texto oscuro.
4. img-fluid: la imagen no se sale de su caja.
5. mx-auto: se centra a sí mismo horizontalmente (con d-block).
